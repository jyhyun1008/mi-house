# mi-house

미스키 계정을 그대로 **개인 홈페이지**로 만들어 주는 클라이언트 (Nuxt 4, 순수 클라이언트 SPA, 별도 서버 없음).

타임라인 대신 미스키에 숨어 있는 기능들을 홈페이지의 메뉴로 씁니다.

| 홈페이지 메뉴 | 미스키 기능 |
| --- | --- |
| **Board** (글·소설·설정) | 페이지 (`users/pages`) |
| **Gallery** | 갤러리 게시물 (`users/gallery/posts`). 그 시절 비툴 커뮤 게시판처럼 테두리 썸네일 격자, Total/Page, 번호 페이지, 제목·내용 검색, 이전/다음 그림 |
| **Scrap** / 개별 게시판 | 공개 클립 (`users/clips`, `clips/notes`): 목록형 또는 스크랩북(이미지 격자) |
| **Guestbook** | 노트 하나에 달린 답글. 비밀글은 주인만 볼 수 있는 "지정 공개" |
| **Web Clap** (박수) | 방명록 노트의 👏 리액션, 또는 로그인 없이 세는 박수(`api.chigoa.me`) + 💌 한마디를 네퀘돈 익명 질문으로 전달 |
| **Q&A** | [네오-퀘스돈](https://neo-quesdon.serafuku.moe) 답변 (`api.chigoa.me`가 중계) |
| **Diary** | 노트 (해시태그로 거를 수 있음) |
| **About** | 프로필, 추가 정보 필드 |
| **Page** | 페이지 하나를 메뉴로 |

## 해시태그 카테고리

Gallery, Board(클립), Diary는 오른쪽 **CATEGORY** 상자에 해시태그를 카테고리처럼 모아 보여줘요. 누르면 그 태그만 걸러지고, 주소에 `?tag=`로 남아서 카테고리 링크를 공유할 수 있어요.

- 갤러리: 게시물 설명에 쓴 `#태그`
- 클립·일기: 노트의 해시태그 (Diary 전용 태그는 빼고)
- 갤러리는 전부(최대 1000개) 불러와서 세고, 클립·일기는 불러온 글 기준으로 세요. 일기에서 카테고리를 고르면 맞는 글이 나올 때까지 지난 노트를 600개까지 더 읽어 와요.

## 레이아웃과 테마

모든 홈페이지는 화면 위아래·양옆으로 넓게 펼쳐지는 **갠홈 레이아웃**이에요.

- **왼쪽 칸 (고정)**: 큰 타이틀과 프로필(박수·방문자 로그인). 어느 메뉴에 가도 그대로 있어요.
- **오른쪽 칸**: Top에서는 시계, Latest(글·갤러리·클립·메모·방명록을 태그로 구분), Notice, **Banner**, 메인 이미지(세로 카드, 선택)가 채우고, Gallery·Board·Scrap 같은 메뉴는 이 자리에 창으로 열려요. × 누르면 Top으로 돌아가요.
- **메뉴**: 왼쪽에 떠 있는 아이콘 독. 아이콘은 [Phosphor Icons](https://phosphoricons.com)(MIT)이고, 테마마다 굵기가 달라요(글래스 light, 페이퍼 duotone, 프레임 thin, 레트로 bold).
- **좁은 화면**: 한 줄로 쌓이고 독은 아래로 내려가요. 메뉴 안에서는 프로필을 숨겨 내용이 먼저 보여요.

테마는 분위기만 바꿔요.

| 테마 | 느낌 |
| --- | --- |
| 글래스 (기본) | 반투명 유리 패널. 배경 사진이 비쳐 보여요 |
| 페이퍼 | 종이 질감, 카드, 마스킹테이프. 스크랩북 느낌 |
| 프레임 | 화면을 감싸는 이중선 액자와 모서리 장식, 각인 같은 세리프 |
| 레트로 | 제목 표시줄(◆ … _ □ ×) 달린 작은 창들, 도트 배경. 그 시절 갠홈 느낌 |

예전 스킨으로 저장된 설정은 가까운 테마로 바뀌어요(동인 → 레트로, 비툴 → 프레임, 아보카도 → 글래스, 심플 → 페이퍼).

**배너**: 관리 → 배너에서 내 배너(보통 200×40)와 친구 배너를 걸어요. 방문자는 내 배너를 눌러 배너 주소와 링크 주소를 복사해 갈 수 있어요.

글꼴은 **부산단디** 서체를 써요. 본문은 단디고딕, 제목은 단디명조, 부제·날짜·푸터 같은 작은 글씨는 단디손글씨가 기본이고, 관리에서 본문·제목 글꼴을 따로 바꿀 수 있어요(도트 글꼴 Mona12, 프리텐다드, 본명조(Noto Serif KR)도 선택 가능).
프리텐다드와 본명조는 크기가 커서, 고른 홈페이지에서만 글자 범위별로 나뉜 스타일시트(jsDelivr)를 불러와요. 둘 다 SIL OFL이라 따로 출처 표시는 필요 없어요.
부산단디 서체의 저작권은 부산광역시에 있고 공공누리 제1유형(출처표시) 조건으로 써요. 그래서 홈페이지 푸터에 출처가 표시돼요. 글꼴 파일은 눈누(noonnu)가 jsDelivr로 제공하는 주소를 그대로 불러와요.
모든 테마는 관리에서 고른 강조색이 배경, 패널, 글자, 테두리와 장식에 섞여 들어가요.
강조색, 메인 이미지, 배경 이미지, ENTER 화면(주의사항 + ENTER/EXIT), 공지, 푸터, 사용자 CSS(`@scope (.mh-site)`로 사이트 안에만 적용)도 고를 수 있어요.
저장하기 전에 주소 뒤에 `?skin=paper`처럼 붙이면 다른 테마를 미리 볼 수 있어요.

## 주소

```
/                       처음 화면 (방문, 로그인, 내 계정)
/@아이디@서버            홈페이지 Top
/@아이디@서버/gallery    …/pages, …/clips, …/diary, …/guestbook, …/about
/@아이디@서버/admin      관리 (주인으로 로그인했을 때만)

https://내도메인/        커스텀 도메인에서는 /@아이디@서버 없이 /gallery, /admin …
```

## 커스텀 도메인

주인은 **관리 → 도메인**에서 자기 도메인(`home.example.com`)을 등록하고, 거기 나오는 안내대로 Cloudflare Worker를 하나 만들면 돼요. 그러면 `https://home.example.com/gallery`처럼 내 도메인 주소로 홈페이지가 열려요.

- Worker 코드는 관리 화면이 그 홈페이지에 맞춰 만들어 줘요(`app/utils/domain.ts`의 `workerScript`). 이 앱의 `_nuxt/` 파일은 그대로 넘겨주고, 나머지 주소에는 `index.html` 머리에 `<meta name="mi-house-site" content="@아이디@서버">`, `<meta name="mi-house-app" content="앱 주소">`를 붙여 보내요.
- 앱은 이 meta를 보면 라우트에서 `/@아이디@서버`를 떼요(`app/router.options.ts`). 다른 사람 홈페이지나 처음 화면 링크는 앱 원래 주소로 가요.
- 설정의 `customDomain`과 지금 도메인이 같을 때만 열려요. 남의 홈페이지를 자기 도메인에 걸어 둘 수 없어요.
- 등록하면 배너의 Link 주소도 그 도메인으로 바뀌어요. 로그인 토큰은 도메인마다 따로 저장돼요.

## 서버 없이 동작하는 방식

- **설정**은 주인 계정의 공개 페이지 `mi-house`(`/@아이디/pages/mi-house`)에 JSON 코드 블록으로 저장됩니다.
  방문자는 로그인하지 않아도 `pages/show`로 읽을 수 있습니다. 이 페이지를 지우면 기본 설정으로 돌아갑니다.
  누구나 자기 설정 페이지를 직접 고칠 수 있으므로, 읽을 때 모든 값을 검증합니다(`app/utils/site.ts`의 `normalizeConfig`).
- **보기**: 모든 내용은 방문자의 브라우저가 홈페이지 주인의 서버 API를 직접 부릅니다(Misskey API는 CORS를 허용합니다).
  같은 서버 계정으로 로그인한 방문자는 그 계정으로 불러오므로 좋아요 상태나 자기가 쓴 비밀글도 보입니다.
- **다른 서버의 방문자**: 방명록과 박수는 방문자 서버의 `ap/show`로 노트를 가져온 뒤 거기서 답글이나 리액션을 남깁니다.
  페이지·갤러리 좋아요는 미스키 구조상 같은 서버 계정만 누를 수 있어서, 다른 서버 방문자에게는 원본 링크를 보여줍니다.
- **로그인**은 MiAuth이고, 토큰은 브라우저 `localStorage`에만 저장됩니다.

## 실행

```bash
npm install
npm run dev        # http://localhost:3224
npm test           # 설정 검증, 사용자 CSS 정리, 주소 파싱 테스트
npm run typecheck
```

정적 호스팅: `npm run generate` 후 `.output/public`을 배포하세요. 모든 경로를 `index.html`로 보내는 SPA fallback이 필요합니다(예: nginx `try_files $uri /index.html;`).

### GitHub Pages

`.github/workflows/pages.yml`이 main에 push할 때마다 테스트, 빌드, 배포를 해요.

1. GitHub에 저장소를 만들고 push
2. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로
3. 첫 배포가 끝나면 `https://<아이디>.github.io/<저장소>/`에서 열려요

- 하위 경로(`/<저장소>/`)는 워크플로가 `NUXT_APP_BASE_URL`로 알아서 맞춰요. 커스텀 도메인을 쓰면 `/`로 빌드돼요.
- GitHub Pages는 SPA fallback이 없어서, Nuxt가 만드는 `404.html`(앱과 같은 내용)이 `/@아이디@서버` 같은 주소를 받아요. 화면은 정상이지만 HTTP 상태는 404예요.
- MiAuth 콜백은 `https://<아이디>.github.io/<저장소>/callback`으로 자동 설정돼요.

## miscord와 공유하는 코드

MiAuth 흐름, API 호출, MFM 렌더링, 페이지 텍스트와 블록 사이 변환(`# 섹션`, `::: 접기`, `![이미지](file:ID)`, 표·목록)은 miscord에서 가져왔습니다.
그래서 miscord로 쓴 페이지도 똑같이 보이고, 접기 섹션도 그대로 동작합니다.
